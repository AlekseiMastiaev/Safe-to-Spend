# ADR-005: Денежные значения хранятся целыми числами

- Статус: принято
- Дата: 2026-08-07

## Контекст

Денежные значения могут содержать копейки. Двоичное представление дробных чисел JavaScript создаёт ошибки вида:

```ts
0.1 + 0.2 !== 0.3;
```

Приложение также должно принимать пользовательские строки с пробелами, запятой или точкой и выражения только со сложением.

## Решение

Все денежные значения хранятся как целые числа в минимальных денежных единицах.

```text
1 ₽       = 100
1 500 ₽   = 150000
250,50 ₽  = 25050
```

В TypeScript используется семантический псевдоним:

```ts
type Money = number;
```

Каждое значение должно быть целым безопасным числом в допустимом диапазоне.

Преобразование ввода выполняется отдельными чистыми функциями. Выражение платежа:

```text
1 000 + 250,50 + 99.50
```

разбирается в массив положительных значений в копейках. `eval` и другие средства исполнения строки запрещены. Поддерживается только оператор `+`.

## Последствия

Положительные:

- сложение и вычитание не накапливают дробную погрешность;
- формат хранения однозначен;
- доменные функции получают нормализованные значения;
- парсер можно проверить отдельными unit-тестами.

Отрицательные:

- ввод и отображение требуют явного преобразования;
- деление для дневного лимита требует определённого правила округления;
- необходимо проверять `Number.isSafeInteger` и диапазон суммы.

## Рассмотренные альтернативы

### Рубли как дробный number

Отклонена из-за ошибок IEEE 754.

### Хранение сумм строками

Отклонена: усложняет сортировку, агрегацию и проверку корректности.

### Decimal-библиотека

Не требуется в MVP: для одной валюты и точности до копейки достаточно целых чисел.
