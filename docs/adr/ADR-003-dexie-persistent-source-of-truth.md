# ADR-003: Dexie и IndexedDB являются источником постоянных данных

- Статус: принято
- Дата: 2026-08-07

## Контекст

Приложению требуется постоянное локальное хранение нескольких связанных коллекций: месяцев, доходов, шаблонов, обязательств, платежей, свободных расходов и настроек.

Одновременное хранение полной копии финансовых данных в Pinia и IndexedDB создаст два конкурирующих состояния.

## Решение

IndexedDB является источником постоянных финансовых данных. Dexie используется как типизированный слой доступа к IndexedDB.

Поток записи:

```text
Component
  → Use case
  → Repository
  → Dexie
  → IndexedDB
```

Поток чтения:

```text
IndexedDB
  → Repository query
  → Composable
  → Component
```

Pinia может хранить только временное состояние приложения, например:

- выбранный месяц, синхронизированный с route;
- глобальные уведомления;
- временное состояние навигации;
- открытый диалог, если он управляется глобально.

Доходы, обязательства, платежи и свободные расходы не дублируются в Pinia как отдельный постоянный источник.

Компоненты не обращаются к объекту Dexie напрямую. Доступ к таблицам изолируется repository-контрактами.

## Последствия

Положительные:

- после перезагрузки используется одно авторитетное состояние;
- реактивное чтение может обновлять UI после изменений базы;
- repository можно заменить тестовым double;
- транзакции и запросы сосредоточены в инфраструктурном слое;
- компоненты не зависят от схемы IndexedDB.

Отрицательные:

- для реактивного UI требуется адаптер или composable поверх запросов;
- ошибки базы должны проходить через use case до понятного сообщения;
- транзакционные операции нескольких таблиц требуют явной реализации.

## Рассмотренные альтернативы

### Pinia как основное хранилище с последующей синхронизацией

Отклонена: появляется риск рассинхронизации и неопределённый порядок восстановления состояния.

### Прямые вызовы Dexie из компонентов

Отклонена: UI становится связанным со схемой базы, транзакциями и деталями запросов.

### localStorage

Отклонена из-за отсутствия подходящей модели коллекций, индексов и транзакций.
