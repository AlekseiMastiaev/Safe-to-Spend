# ADR-010: Вычисляемый перенос остатка между бюджетами

- Статус: принято
- Дата: 2026-10-14

## Контекст

После окончания месяца неиспользованные средства должны участвовать в бюджете следующего
месяца. Показатель экономии обязательств для этого недостаточен: освобождённая сумма могла
быть потрачена. Пользователь может исправлять операции прошлого месяца.

Сохранение вычисленной суммы как обычного дохода создало бы второе финансовое состояние,
потребовало каскадных записей при исправлениях и защиты от дубликатов на нескольких устройствах.

## Решение

`BudgetReadRepository.readMonth(monthKey, currentMonthKey)` читает согласованный снимок истории
до выбранного месяца. Dexie использует одну read-only транзакцию нескольких таблиц; Supabase —
одну SQL RPC с `security invoker`, RLS и фильтрацией по `auth.uid()`.

Одна чистая доменная функция последовательно вычисляет бюджеты. Положительный безопасный
остаток предыдущего существующего бюджета добавляется в принимающий бюджет как вычисленная
строка полученного дохода. Будущие месяцы получают перенос только после наступления. При
пропуске месяцев источником остаётся последний существующий бюджет; дефицит не переносится.

Вычисленная строка имеет стабильный идентификатор, ссылку на источник и не допускает записи
через income repository. Экспорт содержит исходные операции и метаданные месяцев; отдельной
суммы переноса в резервной копии нет. После исправления истории переносы восстанавливаются
повторным чтением без дополнительных записей.

Текущий месяц создаётся атомарной идемпотентной командой только после начала бюджета. Она
копирует открытые снимки планов из последнего предыдущего месяца, сохраняет флаг проверки
планов и не копирует платежи. Первое успешное изменение обязательства или платежа атомарно
сбрасывает флаг; флаг переживает перезапуск и синхронизируется между устройствами.

## Последствия

- Перенос отражает записанные расходы, открытые резервы и поздние исправления истории.
- Повторное чтение не создаёт дубликаты доходов и не меняет исходные операции.
- Для расчёта нужно читать историю до выбранного месяца; чтение выполняется одним снимком,
  без отдельного сетевого запроса на каждый месяц.
- Миграция Supabase добавляет метаданные и RPC до публикации нового frontend. Старые записи
  совместимы: отсутствующий локальный флаг означает `false`; денежные записи не мигрируют.
- При обновлении сохраняется экран с последними данными. Ошибка фонового чтения отображается
  рядом с ними, а смена пользователя или месяца очищает данные предыдущего контекста.
